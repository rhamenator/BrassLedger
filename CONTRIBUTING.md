# Contributing

Thank you for contributing.

1. Open or link an issue for non-trivial changes.
2. Keep each pull request focused and explain user-visible and compatibility effects.
3. Add or update automated tests and run the repository's documented checks locally.
4. Complete the pull-request traceability and verification sections.
5. Do not include secrets, personal data, generated build output, or unrelated formatting changes.

Changes are reviewed under [`docs/DO-178C-ASSURANCE-POLICY.md`](docs/DO-178C-ASSURANCE-POLICY.md). The policy is an engineering-assurance baseline and is not a claim of airborne certification.

Security vulnerabilities must follow [`SECURITY.md`](SECURITY.md), not a public issue.
